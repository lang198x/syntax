# Plan: the tree core

**Status:** In progress. Steps 1 to 5 are done.
**Design:** [shared syntax layer decision](https://github.com/lang198x/lang198x/blob/main/decisions/shared-syntax-layer.md).
**Tracking:** [lang198x/lang198x#1](https://github.com/lang198x/lang198x/issues/1).

Build the parts of `lang198x-syntax` that the Z80 family parser needs first.
Each step is one pull request that passes format, Clippy, tests and the 95%
coverage floor on its own.

Provenance tables wait until the Z80 parser expands macros. Navigation grows
only as that parser asks for it.

## Steps

### 1. Text positions and ranges (done)

- **Files:** `crates/syntax/src/text.rs`.
- **What:** `TextSize` and `TextRange`. Offsets are 32-bit. Every operation is
  checked, and slicing never panics.
- **Verified by:** unit tests and doctests, including overflow, empty ranges
  and slices that end inside a multi-byte character.

### 2. Kinds (done)

- **Files:** `crates/syntax/src/kind.rs`.
- **What:** `SyntaxKind`, a `u16` that each language numbers for itself. A
  small reserved range covers the shared kinds: whitespace, newline, comment,
  error and verbatim. Languages start numbering above it, at 16.
- **Verified by:** tests that the shared kinds are recognised, and that no
  language kind can be built inside the reserved range.

### 3. Storage and the builder (done)

- **Files:** `crates/syntax/src/tree.rs` (private storage),
  `crates/syntax/src/builder.rs`.
- **What:** one flat array of entries in source order. Each entry holds its
  kind, start, length, parent and subtree size, and the source text is stored
  once. The builder offers `start_node`, `token`, `finish_node`, `checkpoint`
  and `start_node_at`. Tokens consume the source in order, so the tree covers
  the whole text by construction. `finish` returns the tree, or an error if
  nodes are unbalanced or the tokens do not cover the text exactly. It never
  panics.
- **As built:** errors are sticky. The first misuse is recorded, later calls
  are ignored, and `finish` returns it, so a parser makes its calls without
  checking each one. A tree has exactly one root node, and every token sits
  inside a node. Empty tokens are allowed, to mark a position. A checkpoint
  from another builder is refused rather than trusted.
- **Verified by:**
  - unit tests for each misuse: an unfinished node, an extra `finish_node`, a
    token past the end of the text, text left uncovered, and a checkpoint used
    after the nodes it relied on have closed;
  - a `proptest` property: any sequence of builder calls either produces a tree
    that passes its own consistency check, or returns an error. Half the
    sequences are completed (root opened, rest of the text tokenised, nodes
    closed), because otherwise only about 1 in 1,700 builds a tree;
  - a property that joining every token's text gives back the input.

### 4. Navigation (done)

- **Files:** `crates/syntax/src/node.rs`.
- **What:** `SyntaxNode` and `SyntaxToken` handles, cheap to copy. They give
  kind, range, text, parent, children, siblings, ancestors and descendants,
  plus `token_at_offset` and `covering_element`. Storage stays private.
- **Verified by:** tests on hand-built trees, and a property that walking the
  descendants visits every entry exactly once, in source order.
- **As built:** `SyntaxTree` is a shared handle (an `Arc` around the private
  storage), and each node and token holds one plus an index. Handles are
  cheap to clone and carry no lifetime, so front ends can store and cache them
  and send them between threads; the tree lives as long as any handle. We
  chose this over borrowed handles before any language used them, because
  switching later would break every front end. The cost is a reference-count
  update per clone, which the decision's 10% benchmark rule would catch. `token_at_offset` and `covering_element` walk down from the node
  rather than scanning it. Empty tokens are never returned by
  `token_at_offset`, and an empty range on a boundary is covered by the first
  element that touches it. Further properties check children, siblings and
  ancestors against each other, and both offset lookups against a full
  search.

### 5. Diagnostics and the parse result (done)

- **Files:** `crates/syntax/src/diagnostic.rs`.
- **What:** a `Diagnostic` with a range, a kind (*unsupported*, *invalid* or
  *unknown*) and a message, kept in a list beside the tree. A `Parse` value
  holds both.
- **Verified by:** unit tests, and a test that diagnostics keep their ranges
  when attached to a tree.
- **As built:** messages are owned strings, so they can name what they found.
  `Parse::new` refuses a diagnostic whose range runs past the text or splits a
  character, so every diagnostic can be shown against the source.

### 6. Snapshot dumps and the checker

- **Files:** `crates/syntax/src/dump.rs`, `crates/syntax/src/snapshot.rs`.
- **What:** a text dump of a tree, one element per line, indented by depth,
  showing kind, range and, for tokens, the quoted text. A checker compares a
  dump with an expected `.tree` file. Setting `LANG198X_BLESS=1` rewrites the
  expected files instead. Kinds print by name through a lookup each language
  supplies.
- **Verified by:** snapshot tests in this crate, plus a test that the checker
  fails on a mismatch, so it cannot pass while checking nothing.

### 7. Fuzz targets

- **Files:** `fuzz/` (its own workspace), with targets for builder call
  sequences and for building a tree from arbitrary text with a toy lexer.
- **What:** `libfuzzer-sys` run with `cargo-fuzz`, as approved for AMOS.
- **Verified by:** a bounded local run of each target, with its duration
  recorded in the pull request.

## Afterwards

- The Z80 family parser (`lang198x/z80-asm`) starts once steps 1–6 are merged.
  It runs the round-trip check over every source in the verdict corpus,
  because that needs a real lexer.
- Provenance tables arrive with the Z80 parser's macro expansion.
- Releases are automated: release-plz opens a release PR, and merging it
  publishes to crates.io through trusted publishing. 0.1.0 was published by
  hand.
